# JM Visual — сайт 3D-визуализатора интерьеров

Портфолио-сайт с параллакс-анимациями, двумя языками (русский и английский) и
собственной админкой: проекты, цены и контакты редактируются прямо в браузере,
без разработчика и без правки кода.

- **Стек:** Next.js 16 (App Router, Turbopack), React 19, Tailwind CSS 4, Motion, Lenis
- **Хостинг:** Vercel (бесплатного тарифа хватает)
- **Хранилище:** Vercel Blob для изображений и данных, локально — папки в проекте

---

## Быстрый старт

```bash
npm install
npm run seed
npm run dev
```

Сайт откроется на <http://localhost:3000>, админка — на <http://localhost:3000/admin>
(пароль по умолчанию `admin`).

`npm run seed` наполняет сайт шестью демо-проектами с процедурно
нарисованными изображениями — чтобы сразу увидеть, как всё выглядит с
контентом. Удалить демо: `npm run seed -- --clean` либо удалить проекты в
админке по одному.

## Структура

```
app/
  (site)/[locale]/        публичный сайт: главная, портфолио, кейс, услуги, контакты
  (admin)/admin/          админка: вход, проекты, заявки, настройки
  api/admin/              загрузка изображений
components/
  site/                   блоки сайта
  admin/                  интерфейс админки
  motion/                 анимации: параллакс, появления, курсор, плавная прокрутка
lib/
  content.ts              чтение и запись проектов
  leads.ts                заявки (хранятся зашифрованными)
  storage/                два хранилища: локальное и Vercel Blob
  i18n/                   тексты интерфейса на двух языках
  defaults.ts             стартовое наполнение: услуги, цены, вопросы
proxy.ts                  определение языка и защита админки
scripts/                  генерация демо-контента
```

## Переменные окружения

Локально создайте файл `.env.local`, на Vercel те же значения задаются в
**Settings → Environment Variables**. Образец — в `.env.example`.

| Переменная | Обязательна | Зачем |
| --- | --- | --- |
| `ADMIN_PASSWORD` | да (на проде) | пароль для входа в `/admin` |
| `SESSION_SECRET` | да (на проде) | подпись сессии и шифрование заявок, от 16 символов |
| `NEXT_PUBLIC_SITE_URL` | желательно | адрес сайта для `sitemap.xml` и ссылок в соцсетях |
| `BLOB_READ_WRITE_TOKEN` | да (на проде) | хранилище изображений Vercel Blob |
| `SITE_BLOB_TOKEN` | нет | запасное имя для токена хранилища, имеет приоритет |
| `NEXT_PUBLIC_METRIKA_ID` | нет | номер счётчика Яндекс.Метрики |
| `TELEGRAM_BOT_TOKEN` | нет | уведомления о заявках в Telegram |
| `TELEGRAM_CHAT_ID` | нет | чат, куда бот пишет заявки |

Без `ADMIN_PASSWORD` и `SESSION_SECRET` проект запускается только в режиме
разработки — с паролем `admin`. В продакшене их отсутствие считается ошибкой
конфигурации: сайт скажет об этом прямо, вместо того чтобы молча пустить
кого угодно в админку.

**Важно:** при смене `SESSION_SECRET` ранее сохранённые заявки перестанут
читаться — они зашифрованы старым ключом. Проекты и настройки это не
затрагивает.

## Публикация на Vercel

1. Залейте репозиторий на GitHub.
2. На [vercel.com](https://vercel.com) → **Add New → Project** → выберите репозиторий.
3. В разделе **Storage** создайте хранилище **Blob** и подключите к проекту —
   переменная `BLOB_READ_WRITE_TOKEN` подставится сама.
4. Добавьте остальные переменные окружения из таблицы выше.
5. **Deploy**. Дальше каждый `git push` обновляет сайт автоматически.
6. Свой домен подключается в **Settings → Domains**.

### Если хранилище не подключается

Проверить состояние можно прямо в админке: **Настройки → Служебное → Проверить
хранилище**. Она пишет в хранилище тестовый файл и показывает, какое хранилище
активно, какие переменные с токеном дошли до сервера и какая из них выбрана.

Что стоит знать про подключение Blob в панели Vercel:

- при подключении хранилища к проекту есть флажок **Add a read-write token env
  var** — без него создаются только `BLOB_STORE_ID` и `BLOB_WEBHOOK_PUBLIC_KEY`,
  а токена, без которого запись невозможна, не будет;
- переменную нужно включить для окружения **Production**, иначе боевой сайт её
  не увидит, и для **Development**, иначе `vercel env pull` не отдаст её скрипту
  переноса;
- хранилище должно быть создано с **публичным** доступом. В приватном нельзя
  сохранять публичные файлы, а сайту они нужны: изображения браузер открывает по
  прямой ссылке с CDN;
- переменные, созданные подключением, Vercel помечает управляемыми и не даёт
  удалить из интерфейса. Если от прежнего хранилища осталась переменная
  `BLOB_READ_WRITE_TOKEN`, она будет перебивать новую. В этом случае добавьте
  свою переменную `SITE_BLOB_TOKEN` с нужным токеном — она имеет приоритет.
  Удалить управляемую переменную можно и через CLI:
  `npx vercel env rm BLOB_READ_WRITE_TOKEN production`.

### Статистика посещений

Считается в двух местах, оба подключения необязательны и независимы.

**Vercel Analytics и Speed Insights** — посещаемость, популярные страницы и
реальная скорость загрузки у посетителей. Кода не требуют: включаются в панели
проекта (**Analytics** → *Enable*, и то же для **Speed Insights**). На тарифе
Hobby доступен бесплатный объём событий, при его исчерпании сбор данных до
конца месяца останавливается.

**Яндекс.Метрика** — источники трафика, поведение на странице, карта кликов и
вебвизор. Показывает то, чего нет в Vercel: по каким запросам пришли, что
смотрели дольше всего, где закрыли страницу.

1. Создайте счётчик на [metrika.yandex.ru](https://metrika.yandex.ru), укажите
   адрес сайта, включите вебвизор.
2. Скопируйте номер счётчика (только цифры).
3. Добавьте переменную `NEXT_PUBLIC_METRIKA_ID` с этим номером — во все три
   окружения — и запустите повторный деплой.

Переменная начинается с `NEXT_PUBLIC_`, потому что счётчик работает в браузере;
её значение видно в исходном коде страницы, и это нормально — номер счётчика не
секрет.

Отправленная заявка отправляется как цель `lead_submitted` в оба сервиса.
В Метрике по ней настраивается цель, и тогда видно, какие страницы и источники
приводят заказчиков. Переходы между страницами сайта учитываются вручную:
сайт работает без перезагрузок, и счётчик иначе засчитал бы только первый экран.

Админка из подсчёта исключена — считаем посетителей, а не свои заходы в панель.

### Уведомления о заявках в Telegram

1. Напишите [@BotFather](https://t.me/BotFather), команда `/newbot`, получите токен.
2. Напишите своему боту любое сообщение (иначе он не сможет ответить первым).
3. Узнайте свой числовой id у [@userinfobot](https://t.me/userinfobot).
4. Добавьте `TELEGRAM_BOT_TOKEN` и `TELEGRAM_CHAT_ID` в переменные окружения.
5. В админке → **Настройки → Уведомления** нажмите «Отправить тестовое сообщение».

Заявки в любом случае сохраняются в админке — Telegram нужен только для того,
чтобы узнавать о них сразу.

## Как пользоваться админкой

**Проекты.** Кнопка «Добавить проект»: название, тип объекта, площадь, год,
описание и кадры. Изображения можно перетащить в область загрузки — сразу
несколько. Первый кадр становится обложкой, но обложку можно назначить любую.
Порядок кадров меняется стрелками.

Проект сохраняется как черновик и не виден на сайте, пока не нажать
«Сохранить и опубликовать». Переключатель «В избранном» выводит работу в
подборку на главной.

**Заявки.** Все обращения с сайта. Непрочитанные отмечены точкой, кнопка
«Ответить» открывает почту, телефон или Telegram — в зависимости от того,
что оставил заказчик.

**Настройки.** Название сайта, тексты первого экрана, контакты и соцсети,
прайс с описанием услуг, частые вопросы и цифры о себе. Всё редактируется на
двух языках: переключатель `ru / en` стоит у каждого поля. Если английский
перевод не заполнен, сайт покажет русский текст — пустых мест не будет.

Изменения появляются на сайте сразу после сохранения.

## Качество изображений

Оригинал загружается в хранилище **без сжатия и без уменьшения** — на сайте
показывается ровно тот файл, который просчитали. Дополнительно браузер готовит
два лёгких превью (до 2048 px и до 800 px): они используются только в сетке
работ, где кадр физически занимает пару сотен пикселей.

В **Настройках → Главная** есть переключатель «Показывать изображения в
исходном качестве»:

- **включён** (по умолчанию) — крупные планы отдаются оригиналами;
- **выключен** — крупные планы проходят через оптимизацию Next.js с качеством
  95, а оригинал остаётся в полноэкранном просмотре по клику.

Второй режим стоит попробовать, если страницы начнут ощутимо тормозить на
мобильном интернете: разница в качестве почти незаметна, а вес страницы
падает в разы.

На Vercel файлы уходят из браузера прямо в Blob, минуя серверную функцию, —
поэтому ограничение в 4,5 МБ на запрос не мешает загружать тяжёлые рендеры
(лимит — 200 МБ на файл).

## Анимации

Плавная прокрутка (Lenis) задаёт ритм, на который опираются параллакс-слои,
построчное появление заголовков, горизонтальная лента избранных работ и
кастомный курсор. Всё построено только на `transform` и `opacity`, поэтому
работает на видеокарте и не вызывает переверстки страницы.

Если в системе включено «уменьшение движения» (`prefers-reduced-motion`),
анимации выключаются, инерционная прокрутка останавливается, а сайт остаётся
полностью рабочим.

## Где лежат данные

| Что | Локально | На Vercel |
| --- | --- | --- |
| Проекты и настройки | `.data/content__site.json` | Blob, `content/site.json` |
| Заявки | `.data/content__leads.enc` | Blob, `content/leads.enc` (зашифровано) |
| Изображения | `public/uploads/` | Blob, `uploads/<год>/` |

Локальные папки `.data` и `public/uploads` в git не попадают. Чтобы сделать
резервную копию контента с боевого сайта, достаточно скачать `content/site.json`
из хранилища Blob в панели Vercel.
